# 更新日志

本文件记录 RM_AI_NPC 的版本变更要点。
**逐版完整说明（每处 bug 的成因、修法、验证项）见仓库根目录的 [`安装说明.txt`](../安装说明.txt)。**

> ★ **插件本体 `RM_AI_NPC.js` 与 `tools/` 是两个独立目录，必须同版本号一起换。**
> 只换插件不换 `tools/`，老引擎上的「一键准备」照样跑不起来。

版本号规则：`主版本.次版本.修订号`。自 v2.9 起，「一键生成世界书 / 世界设定 / 角色设定」成为主线。

## [v2.10.5] — 修掉 v2.10.4 自己引入的五处 bug

v2.10.4 刚把「所有角色都把玩家当陌生人」修好，紧接着的审计查出**五处真问题**，其中第一处正好把这次修复**反向放大**。全部已修，补了 23 项守门员断言。

**一、★ 占位值把修复反转（最严重）**

生成要求里写着「没有线索支持就写克制的说法（『素不相识，按平常的分寸对待』）」—— 等于**明令模型写一个占位值**；而读取时用的是裸真值判断（`!!卡.towardPlayer`），非空字符串照样判成「有关系」。于是提示词同一份里同时出现三句自相矛盾的话，而且**对真正的陌生人硬说「你们不是陌生人」** —— 比修复前更糟。

→ 新增 `Ainpc.persona.tieOf()` 统一判定「这个字段到底有没有内容」：trim 后为空、或**整句**就是一个占位词（素不相识 / 无 / 不知道 / none / n/a / `-` …，含日文「面識なし」）一律算「没写」。三处读取全走它。**只匹配整句**，不做「含关键词」匹配。

**二、persona 预算会把开场白挤掉**

人设正文拼成串后 `slice(0, 1600)` 从尾部硬切，而「开场白」排在倒数第二位 —— 新字段插在它前面，长卡里会连带把开场白一起砍掉。

→ 把「与主角的关系」挪到 relations **之后、taboo 之前**，既不挤掉既有字段，又保证在 greeting 前面被保下来。

**三、编辑器里「把整行删掉」不等于「清空」**

解析器只在「认得出这一行」时才建键，玩家删掉整行后保存时走白名单跳过，**旧文案原封不动留在卡里**，提示词里照样生效。（通用缺陷，`name` / `identity` / `relations` 等所有字段都一样。）

→ 编辑器提交时声明 `rec.managed = ACTOR_FIELDS` 全字段名；保存层凡在 managed 里的字段**缺席就写空**。其它不走表单的调用方不传 managed，维持原「没给就保持原样」的合并语义。顺带让 `knowledge` 也归 managed 管。

**四、生成要求那段文案硬编码中文，绕过了语言包**

那段是**要发给模型**的文字，日文 / 英文游戏里模型会突然收到一段中文指令。

→ 新增语言键 `prompt.tieRule`（四语言各一份），老语言包缺这个键时兜底回简体中文。四份文案都保留字段名 `towardPlayer`。

**五、`npcByKey` 缺一层索引守卫**

外层 `Ainpc.persona &&` 只保护了 persona 对象，没保护 `npcIndex`。

→ 改成 `(Ainpc.npcIndex && Ainpc.npcIndex[k]) || null`。防御性加固。

**验证**：`_probe_relation.js` 加第 ⑤ 段共 23 项（17 种占位值全被过滤、4 类真关系描述不许误伤、端到端断言、persona 字段顺序、编辑器三种操作、四语言文案齐全）。12 台测试机全绿（60 项），三个旧探针失败项与 v2.10.3 基线逐台一致，无回归。

**兼容性**：没有新增任何配置项，不用改 `config.json`；老存档 / 老世界书 / 老 `config.json` 全部兼容。工具链（`tools/`）一个字没改。

**另**：顺手修掉两个打包器缺陷 —— ① 安装说明的「插入锚点」判据量纲写错，导致锚点那一版被重复插入；② 底稿改为自动挑一份变更记录无重复的最高版本包。

## [v2.10.4] — 别把所有人都当陌生人

> 玩家原话：「角色扮演时，所有角色都是陌生人……Mira 里实验室的老师本来对主角很温柔，态度偏差太大，怎么改？」

这不是「语气没调好」，是**四层各自成立、叠在一起就成了全员路人**：

| # | 问题 | 修法 |
| --- | --- | --- |
| 一 | 默认关系文案整套是**商店口气**（「普通的买卖关系」），可九成以上 NPC 根本不做买卖 | 同一套档位再写一份「不是来做买卖的」版本（`toneNs` / `actNs`，四语言），`relationBrief()` 按 `hasRealShop()` 分流 |
| 二 | 提示词里**从来没有「跟你说话的人是谁」** —— `world_bible.json` 写得很清楚，但只喂给「人设工坊」，对话提示词一次都没读过 | 新增 `Ainpc.protagonist()` 懒加载主角档案，`buildMessages` 拼出 `prompt.worldYou`（四语言）；生成圣经后立刻 `reloadProtagonist()` 清缓存 |
| 三 | 人设卡里**没地方写「他和主角什么关系」** —— 铁律 8 要求 relations 只能写本组名单里的人，主角不在名单里 | 卡片新增字段 `towardPlayer`（该铁律的**唯一例外**）；进对话提示词、资料馆卡片、字数统计、保存白名单与编辑器。**留空不兜底** |
| 四 | 「今天才第一次打交道」字面没错，模型却极易读成「不认识」 —— 说的本来是**交情**从零开始 | 新增 `prompt.strangerKnown` 变体：有人设卡写了关系时改用它，明说「交情从零，身份照旧」 |

**老机器一条都不受影响**：没圣经 → 少一段，照常跑；没有人设卡 → 走原来的 stranger / firstMeet；商人 → 走原来的买卖口气。本版没有新增任何配置项，工具链一个字没改。

**验证**：新增守门员 `_probe_relation.js`（37 项）。12 台测试机全绿。

## [v2.10.3] — 翻页改回「按下确定键」+ 人设同步到角色面板

> 玩家原话：「两个问题：mira 文本框仍然错行，交互时文字还会自动下一页，不如改成点一下再下一页；人设同步有问题，写好的人设没有同步到当前地图显示的角色设定的面板上。」

**一、自动下一页 —— 真凶是插件自己的一个钩子（外加一款第三方插件）**

插件的 `updateInput` 钩子**每一帧都无条件把 `pause` 清成 false**，副作用是**把玩家的按键判定整个跳过了** —— 引擎的翻页只发生在 `if (this.pause) { if (this.isTriggered()) … }` 分支里，`pause` 先被清掉就永远进不去。深挖还发现《Mira》装了 `CU_TimeNextMessageMode`（按时间自动翻页），它覆写了 `isTriggered`，于是「玩家按键」和「时间到」在引擎眼里变成同一件事。

→ **把 `pause` 还给引擎**：① `startPause` 不再清 pause；② `updateInput` 不再无条件清 pause；③ 兜底帧数**自己数**（`_ptFrames`，不能用引擎的 `_waitCount`）；④ AI 对话期间把 `isTriggered` 收到**只认玩家真实输入**，把第三方的自动推进挡在外面。

**二、文本框仍然错行 —— 折行宽度不再「照公式猜」**

原来用 `boxWidth − padding×2 − 168`，只在引擎原版下成立；有插件改了 `newLineX` / 行高 / 立绘宽度时就会对不上。

→ 只要场景里真有消息窗，就用它的 `contentsWidth()` 与 `newLineX()` 实时算，两边取更保守的那个；量不到（无头测试）才退回公式。**通用修法，不是给某一款游戏打补丁。**

**三、人设没同步到角色面板 —— 面板那一行只读原作身份，不看人设卡**

→ 菜单改为**以人设卡为准**：名字取卡里的名字、身份取卡里的 `identity`；有卡的人画一个 `✎` 标记；本图没人时把其它地图上已写人设的角色附在下面（最多 12 个），按**写入时间倒序**；工坊跑完顺手清掉资料馆详情页缓存。

**验证**：新增守门员 `_probe_sync.js`（37 项，四台全绿）。本版没有新增任何配置项，工具链一个字没改。

## [v2.10.1] — 「Ctrl 单独生成」按了没反应

> 玩家原话：「Ctrl 单独生成角色卡的功能在呆呆里没有效果」「把单独生成角色设定的功能新增到互动中，这样就可以只和要对话的角色 AI 扮演了」

**一、为什么「没有效果」—— 三处「什么都不做、也不说为什么」**

① 「AI 角色」菜单里光标停在功能项上 → 直接 `return`；② 资料馆「🎭 角色」栏第 0 行是「角色　总览」，**光标默认停在那儿**，第一次按 Ctrl 必然落空；③ 资料馆的世界书 / 世界设定两栏按 Ctrl 压根没有分支。

→ 现在**每一种落空都有话说**：本图没角色 → 告诉他按 Tab 看别的图 / 进资料馆；光标在功能项上 → 提醒往下选一个人；进错栏 → 提醒按 ←→ 切过去。

**二、新功能：走进正在聊的那个人的身边去补人设**

「互动…」子菜单里多了一项「✎ 单独生成角色设定」，**对话中按 Ctrl 同效**。写完**这一场对话立刻按新卡演**。他要是还没被交给 AI，顺手交出去 —— 于是「只跟想聊的那个人 AI 扮演」从四步变成「聊着聊着按一下 Ctrl」。已经开着的人不受影响。

**三、顺手修掉「生成了个莫名其妙的东西」**

单人生成的线索里人名原来优先取**原始演员名**（素材名如 `C:SF_Actor1`），卡里的名字也跟着错。→ 一律以显示名（`Ainpc.displayName`）为准，原始值另存 `rawActorName` 备查。

**验证**：新增守门员 `_probe_genone.js`（呆呆 35/0 · Mira 35/0 · 伊莉莎 33/0）。本版没有新增任何配置项，工具链一个字没改。

## [v2.9.3] — 老引擎兼容

Mira 这类 NW.js 0.12 / Chromium 41 的游戏，以前放进这类老引擎游戏，菜单里**根本没有「AI 角色」** —— 不是菜单没挂上，是整份脚本在编译阶段就失败了。三处一起修好：

- **插件本体**：删掉两处「对象字面量的重复属性名」（ES5 严格模式下是 SyntaxError，Chromium 41 直接拒绝整份文件）；`Array#find` 换成 ES5 写法。
- **游戏内工具**：`www/ai_npc/tools/` 下那批脚本整体降到 ES5 —— 它们不是普通命令行脚本，插件是用 `new Function` 把它们塞进**游戏自己的 Node** 里执行的；缺的 `Object.assign` / `entries` / `values`、`Array#find` / `includes`、`String#padStart` / `padEnd` 已就地补齐。
- **配置面板**：面板 CSS 用了 CSS 变量（Chrome 49+），老引擎会把整条声明丢掉、掉成白底黑字。现在每条 `var()` 前面都补了字面值兜底，新引擎行为一字不变。
