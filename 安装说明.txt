==================================================================
 RM_AI_NPC v2.10.5  ——  安装说明（给别人用的那版）
==================================================================

这是什么
  给 RPG Maker MV / MZ 游戏加一层「AI 扮演 NPC」的插件。
  装完以后，你在游戏里能直接打字和 NPC 自由对话、讲价、偷窃、抢劫、切磋、送礼……
  未勾选的角色完全保持原版行为，插件不介入。

你需要准备
  1) 一台 Windows 电脑 + 游戏本体（MV / MZ 引擎，能看到 www/ 目录）。
  2) 一个 OpenAI 兼容的 API Key（DeepSeek / 通义 / OpenAI 都行，看 endpoint 怎么填）。
     不填也能进游戏：会走「仿真模式」，离线跑固定套路，专门用来验证装没装通。

  不需要装 Node.js，不需要敲命令 —— 直接看下面的「装法一」。

------------------------------------------------------------------
 装法一：把游戏文件夹拖到「一键安装.bat」上（最稳，推荐）
------------------------------------------------------------------
  1) 把整个压缩包解压到任意位置（桌面就行，不用放进游戏目录）。

  2) 找到你的【游戏文件夹】—— 里面有 Game.exe，还有一个 www 文件夹。
     把这个文件夹【拖到「一键安装.bat」的图标上】松手。

     拖的是哪个，它就装哪个。拖错了、或者拖的目录里没有游戏，它会直接报错
     停下，不会去别处乱装。
     （拖的目录套了几层也没关系，只要下面 3 层内有 www\data\System.json。）

  3) 另一种同样稳的用法：把压缩包【直接解压进游戏文件夹】，
     然后在游戏文件夹里双击刚解压出来的「一键安装.bat」。
     它一看“包就在游戏里”，二话不说就装这个游戏。

   ⚠ 只把压缩包解压在桌面、然后直接双击 .bat 的话：
     如果电脑里只有一款这种游戏，它会问你一句「装到这个吗」（回车就行）；
     如果有好几款（比如你留了好几份拷贝），它会把候选列出来让你选编号 ——
     它【不会】替你挑一个装上去。

     它替你做完这些，你不用管：
       · 备份 www/js/plugins.js → plugins.js.bak-日期时间（出问题能还原）
       · 把插件复制到 www/js/plugins/RM_AI_NPC.js
       · 在 $plugins 末尾注册插件（必须在最后，才能包住其他插件的钩子）
       · 建好 www/ai_npc/，放上面板 + 配置模板 + 空白配置；
       · 把「一键生成」要用的 10 个脚本铺到 www/ai_npc/tools/，
         提示词模板铺到 www/ai_npc/_lore/ —— 装完即可在游戏内一键生成。

  4) 窗口顶部与结尾都会写明「装到了：<哪款游戏>」，核对一眼再进游戏。
     如果它列了「还发现这些游戏，没动」，而你要装的恰好在那个列表里 ——
     把那个游戏文件夹拖到 .bat 上重跑一次即可。

  然后：启动游戏 → 任意界面按 F10 → 填 API Key
        → 菜单「AI 角色」→「生成角色人设 / 生成世界设定」→ 等它跑完（见下节）。
        → 勾选想交给 AI 扮演的 NPC → 去和它说话。

  ⚠ 菜单找不到？直接用 F10 —— 它不经过游戏输入系统，也不依赖任何菜单。

------------------------------------------------------------------
 填完 Key 之后：一键生成世界书 / 世界设定 / 角色设定
------------------------------------------------------------------
  这就是 v2.9 系列的重点 —— 任何 MV / MZ 游戏，装完、填完 Key，
  在游戏里点一下就能把这些全生出来，不用命令行、不用装 Node.js、不用换包。

  · 打开菜单「AI 角色」→ 选「生成角色人设」或「生成世界设定」→ 确定。
    如果还没准备好，它会【自己先跑一遍前置流水线】，屏幕上逐行显示进度：

      ① 扫原作数据（NPC 名录 / 台词 / 地图）—— 本地，不联网，约 1 秒
      ② 抽取全量语料（所有 NPC 的每句台词）—— 本地
      ③ AI 归纳「世界圣经」（时代 / 地点 / 势力 / 人物 / 术语）—— 1 次调用
      ④ 给主角团挑人设线索 —— 本地
      ⑤ AI 拟「世界设定主题清单」（该写哪些条目）—— 1 次调用
      ⑥ 为每条主题找原作台词作依据 —— 本地

    跑完这一步，世界书 / 世界观 / 角色线索 / 设定线索就全齐了，
    接着它会自动进入正式生成：逐组写角色人设、逐条写世界设定。

  · 前置流水线只在【第一次】跑。以后再点，它一看结果都在，直接跳过。
    想推倒重来：在那一页按 PgUp（强制重跑）。
  · 没填 Key 就点？它会告诉你「缺少 API Key」，不会白跑，也不会写坏数据。
  · 卡住 / 报错：屏幕会把每一步、每一句原因列清楚（哪一步失败、为什么）。
    真机上游刃有余 —— 前置 6 步的产物都会落盘（www/ai_npc/_lore/ 下），
    下次接着跑，不会从头再来。

------------------------------------------------------------------
 装法二：双击没反应 / 被杀毒软件拦了 / 不是 Windows
------------------------------------------------------------------
  A. 装了 Node.js 的话，一条命令（把下面这行贴进命令行回车）：

       node tools/install.js "D:/你的游戏根目录"
       （本包没带成品数据。这一步不跑也没关系 —— 进游戏第一次启动时会自己扫原作数据；
         世界书 / 世界设定 / 角色设定，填完 Key 后在游戏内「AI 角色」菜单一键生成。）

     「游戏根目录」= Game.exe 所在的那一层。路径带空格要用英文双引号包起来。

  B. 手上有耐心？纯手工也行（下面这份可以直接照抄）：

       1) 把 RM_AI_NPC.js 复制到   <游戏>/www/js/plugins/

       2) 用记事本打开   <游戏>/www/js/plugins.js
          在 $plugins 数组最后的 ] 之前，给最后一条补个英文逗号，然后插入这行：

          {"name":"RM_AI_NPC","status":true,"description":"AI NPC",
           "parameters":{"configPath":"ai_npc/config.json",
           "endpoint":"https://api.deepseek.com/chat/completions",
           "apiKey":"","model":"deepseek-chat","maxTurns":"8","debug":"false"}}

          ⚠ 这一条必须排在数组最后。插件要最后加载，才能包住其他插件的钩子。
          ⚠ 保存时选 UTF-8 编码，别存成 ANSI，否则中文描述会变乱码（不影响功能）。

       3) 在 <游戏>/www/ 下新建一个文件夹，名字叫   ai_npc

       4) 把包里这些文件复制进 <游戏>/www/ai_npc/ ：
          （本包没带这三份 —— 不用手动弄：进游戏第一次启动自动扫，
            填完 Key 后在「AI 角色」菜单一键生成。）
          config.template.json   →  复制一份，改名成 config.json
          tools\ 下的一键生成脚本（extract_lore / gen_bible / gen_topics …）
          tools\config-panel.html / config-server.js / 打开配置面板.bat / panel-help.txt
          _lore\ 下的提示词模板（persona / lorebook / bible / topics —— 一键生成要用）

       5) 启动游戏 → 按 F10 填 API Key → 菜单「AI 角色」勾选 NPC。

------------------------------------------------------------------
 装完之后怎么玩
------------------------------------------------------------------
  · 游戏中任意时刻按 F10：打开配置面板（改 Key / 换模型 / 调玩法参数）
  · 菜单「AI 角色」：↑↓ 选人，确定 开关 AI，PageUp/PageDown 全开全关
  · 对话中的选项：买东西 / 讲讲价 /（偷东西）/（动手抢）/ 自由发言 / 先走了
  · 也可以直接打字：「抢劫」「帮我打个折」「这个送我吧」都能被认出来
  · 菜单「AI 角色」→「世界书 / 角色」：资料馆，翻这游戏里所有人物的原作台词

  没勾选的角色一律保持原版，不会乱说话。

------------------------------------------------------------------
 出问题了先看这里
------------------------------------------------------------------
  · 插件到底加载没有 → 打开 <游戏>/www/ai_npc/startup.log（每次启动重写，第一手证据）
  · 菜单里没有「AI 角色」→ 插件没注册成功，或没排在最后。重跑一次「一键安装.bat」。
  · 一键安装.bat 双击一闪而过 → 右键它选「以管理员身份运行」；
    或开个 cmd 窗口手动跑：cd /d "<解压出来的包目录>" 然后 一键安装.bat
  · 杀毒软件拦了 .bat → 它只是不认识新脚本，放行一次即可。
    （脚本只做三件事：备份 plugins.js、复制文件、在 $plugins 末尾加一条记录。）
  · 装错了想还原 → 把 www/js/plugins.js.bak-日期时间 覆盖回 www/js/plugins.js 即可。
    装了 Node 的话也可以跑  node tools/install.js "<游戏根目录>" --uninstall
  · 打开配置面板.bat 双击一闪而过 → 在 cmd 里手动跑一遍，报错就看得见了：
                         cd /d "<游戏目录>" && 打开AI配置面板.bat
  · 严格卸载（连文件一起删）→ node tools/install.js "<游戏根目录>" --uninstall --purge --yes

------------------------------------------------------------------
 别忘了这些
------------------------------------------------------------------
  · 包里的 config.template.json 是空白模板，apiKey 是空的 ——
    也就是说，这个包里不含任何人的 API Key。
    你填完 Key 的那份 config.json 只留在自己机器的 www/ai_npc/ 里，别连它一起发出去。
  · 用的是云端大模型，对话内容会发到对应服务商。介意的话用本地模型（endpoint 指向本地）。
  · 本包【通用】——  装到任何一款 MV / MZ 游戏上，填完 Key 都能一键生成世界书、
    世界设定、角色设定（见上面那节）。这些数据是在【你安装的那款游戏】里、
    用【那款游戏自己的原作台词】现场生成的 —— 所以换任何游戏都成立，不会串味。

  · 包里没预置任何一部作品的成品数据；一切都在游戏内首次生成。
    想省 API 额度、或懒得等，才需要用 -full 包（同一款游戏的成品直接带上）。

 v2.10.5：v2.10.4 那版"关系修复"自己出了五个 bug —— 最狠的一个把修复整个反转
------------------------------------------------------------------

  背景：v2.10.4 刚把「所有角色都把玩家当陌生人」修好（非商人口气 / 主角档案 /
  与主角的关系字段 / 初次见面分流）。紧接着做了一轮审计，查出**五处真问题**，
  其中第一处正好把这次修复反向放大。全部已修，并补了 23 项守门员断言。

  一、★ 占位值把修复反转（最严重）

    生成要求里写着「没有线索支持就写克制的说法（「素不相识，按平常的分寸对待」）」
    —— 等于**明令模型写一个占位值**。而读取时用的是裸真值判断（`!!卡.towardPlayer`），
    占位值是非空字符串，照样判成"有关系"。于是提示词同一份里同时出现：

        你和主角的关系：素不相识，按平常的分寸对待
        这是你和他头一回说话 —— 但你们在身份上并不是陌生人…
        交情是从零开始，但在身份上你们并不是陌生人…

    三句自相矛盾，而且**对真正的陌生人硬说"你们不是陌生人"** ——
    比修复之前更糟。（v2.10.3 根本没有这个字段，纯属新引入。）

    修法：新增 `Ainpc.persona.tieOf()` 统一判定「这个字段到底有没有内容」：
    trim 后为空、或**整句**就是一个占位词（素不相识 / 无 / 不知道 / none / n/a / "-" …，
    含日文「面識なし」），一律算「没写」。三处读取（关系分流 / persona 段 / 首次见面）全走它。
    ★ 只匹配"整句"，不做"含关键词"匹配 ——「你们素不相识，但他知道你叫什么」
      是真描述，不能被误伤。

  二、persona 预算会把开场白挤掉

    人设正文拼成串后 `slice(0, 1600)` **从尾部硬切**，而「开场白」（greeting）
    排在倒数第二位。新字段原本插在 greeting 之前、relations 之后 ——
    长卡里它自己先被砍，还会把开场白一起带走。
    开场白是整场对话给玩家的第一印象，最不该丢。

    修法：把「与主角的关系」挪到 relations **之后、taboo 之前** ——
    既不挤掉既有字段，又保证在 greeting 前面被保下来。
    （实测 162 张真实卡当前最长 1146 字 < 1600，尚未触发；属提前拆掉的地雷。）

  三、编辑器里「把整行删掉」不等于「清空」

    角色设定编辑器会把每个字段的标签都预填出来。玩家想删掉「与主角的关系」时，
    最自然的动作是**把整行删掉** —— 而解析器只在"认得出这一行"时才建键，
    于是保存时白名单跳过、**旧文案原封不动留在卡里**，提示词里照样生效。
    玩家以为删了，其实没删。（这是通用缺陷：name / identity / relations 等所有字段都一样。）

    修法：编辑器提交时声明 `rec.managed = ACTOR_FIELDS 的全字段名`，
    表示"这个表单管辖这些字段"；保存层凡在 managed 里的字段，**缺席就写空**。
    ★ 其它不走表单的调用方不传 managed，维持原来的"没给就保持原样"合并语义。
    ★ 顺带让 knowledge（知道的事）也归 managed 管 —— 删掉那一行同样清空。

  四、生成要求那段文案硬编码中文，绕过了语言包

    那段是**要发给模型**的文字。日文 / 英文游戏里，模型会突然收到一段中文指令。
    修法：新增语言键 `prompt.tieRule`（四语言各一份），playerTieRule() 改读它；
    老语言包没有这个键时兜底回简体中文（总比整段空白强 —— 空白等于没告诉模型有这个字段）。
    ★ 四份文案里都保留字段名 towardPlayer —— 判重靠它。

  五、npcByKey 缺一层索引守卫

    v2.10.4 让关系分流用上了 `npcByKey`，而它直接索引 `Ainpc.npcIndex[k]`；
    外层的 `Ainpc.persona &&` 守卫只保护了 persona 对象，没保护 npcIndex。
    改成 `(Ainpc.npcIndex && Ainpc.npcIndex[k]) || null`。
    （正常路径下 npcIndex 不会为空，属防御性加固。）

  六、守门员与验证

    `_probe_relation.js` 加第 ⑤ 段共 23 项，专盯上面五处：
    17 种占位值必须全被过滤、4 类真关系描述不许被误伤、
    端到端断言「占位值 NPC 拿不到"不是陌生人"那两句」且「真关系仍然生效」、
    persona 字段顺序（必须 relations → 与主角的关系 → taboo → greeting）、
    编辑器三种操作（原样保存 / 整行删掉 / 只清值）的行为、四语言文案齐全、
    以及不带 managed 的老调用方仍维持合并语义。
    12 台测试机全绿（60 项）；三个旧探针的失败项与 v2.10.3 基线逐台一致，无回归。

  七、顺手修掉两个打包器缺陷（与玩法无关，但每次打包都会踩）

    ① 安装说明的"插入锚点"判据量纲写错（`>= 21040000` 永远不成立），
       导致锚点那一版被重复插入 —— v2.10.4 包里的变更记录带 4 组重复标题。
       现在改成"只补比底稿已有版本更新的段落"，并加了**插入后自检重复**。
    ② 底稿改为自动挑一份**变更记录无重复**的最高版本包，避开已经滚脏的那几份。

  八、本版**没有新增任何配置项**，不用改 config.json；
     老存档 / 老世界书 / 老 config.json 全部兼容。工具链（tools/）一个字没改。

 v2.10.4：别把所有人都当陌生人 —— 关系分四层查下来，全是提示词自己作的反
------------------------------------------------------------------

  玩家原话：「角色扮演时，所有角色都是陌生人……Mira 里实验室的老师本来对主角
             很温柔，态度偏差太大，怎么改？」

  这不是"语气没调好"，是**四层各自成立、叠在一起就成了全员路人**：

  一、默认关系文案整套是商店口气

    `aff.tone` / `aff.act` 那五个档位写的是「普通的买卖关系」「价钱按本价，
    不打折也不刁难」—— 可九成以上的 NPC 根本不做买卖。给他们也套这句，
    演出来就是一副店家待客的客气疏远。原作里"老师对学生很温柔"这种天生关系，
    被一句不相干的买卖条款抹平了。

    修法：同一套档位再写一份「不是来做买卖的」版本（`toneNs` / `actNs`，四语言），
    `relationBrief()` 按 `hasRealShop()` 分流 —— 商人仍旧拿原版，其余人走非商人口气。
    老的 / 玩家自己改过的语言包没有这两组时用 `||` 落回原版，不会整段空白。

  二、提示词里从来没有"跟你说话的人是谁"

    world_bible.json 里其实写得很清楚（Mira：米拉·艾亚丽兹，就读于阿维尔的学校，
    为查明体内魔力四处收集素材），可那份文件只喂给「人设工坊」压成世界观，
    **对话提示词一次都没读过**。于是模型压根不知道自己面对的是谁 ——
    老师对学生本该有的那份关照、同学之间本该有的那份熟络，一概无从谈起。

    修法：`Ainpc.protagonist()` 懒加载主角档案（名字 / 身份 / 同行者），
    buildMessages 拼出 `prompt.worldYou` 一段（四语言）。
    ★ 生成圣经之后立刻 `reloadProtagonist()` 清缓存 —— 否则这一局读到的
      还是"这台机器没有圣经"，主角那一段永远缺席。
    ★ 这一段**刻意不走** sanitizeNames：那个函数是把主角名从"NPC 名字"的位置上
      排掉的，而这里恰恰要告诉模型"跟你说话的那个人叫什么"，语境不同。

  三、人设卡里没地方写"他和主角什么关系"

    铁律 8 要求 relations 只能写**本组名单里**的人，主角不在名单里 → 永远写不出来；
    再叠上"初次见面 = 彼此都不认识"，老师对着自己的学生也只能演成公事公办的生人。

    修法：卡片新增字段 `towardPlayer`（人设工坊那条铁律的**唯一例外**，
    要求里写明"没线索就写克制的说法，不要编造深交"）；
    它进对话提示词、资料馆卡片、字数统计、保存白名单与编辑器（认「与主角的关系」

v2.10.3：翻页改成「点一下再下一页」+ 人设同步到角色面板 + 折行宽度按真实窗口量
------------------------------------------------------------------

  玩家原话：「两个问题：mira文本框仍然错行，交互时文字还会自动下一页，
             不如改成点一下再下一页；人设同步有问题，写好的人设没有同步到
             当前地图显示的角色设定的面板上，改一下。」

  一、自动下一页 —— 真凶是**插件自己的一个钩子**（外加一款第三方插件）

    我们那个 `updateInput` 钩子**每一帧都无条件把 pause 清成 false**。
    它的原意是"别让消息窗卡在 pause 上"（否则新注入的台词显示不出来），
    副作用却是**把玩家的按键判定整个跳过了** —— 引擎的翻页 / 收尾只发生在
        if (this.pause) { if (this.isTriggered()) { this.pause = false; … } }
    这个分支里；pause 先被我们清掉，它永远进不去，只能靠倒计时自动继续。

    深挖还发现《Mira》装了 **CU_TimeNextMessageMode**（按时间自动翻到下一句的演出插件），
    它覆写了 `Window_Message.prototype.isTriggered`：原版结果 **或** "时间到则 true" ——
    于是"玩家按键"和"时间到"在引擎眼里变成同一件事。
    （同类还有 TS_MessageAuto 的自动播放、UTA_MessageSkip 的跳过。）

    修法：**把 pause 还给引擎**，翻页回到"按下确定键"这条原生路径 ——
      ① `startPause` 不再清 pause（中间屏与最后一屏都保留）；
      ② `updateInput` 不再无条件清 pause（这正是自动翻页的元凶）；
      ③ 兜底帧数**自己数**（`_ptFrames`）—— 不能用引擎的 `_waitCount`：
         它 > 0 时 `updateWait()` 会直接 return，连带 `updateInput()` 都不调用，
         玩家的按键就被整个吃掉了；自己数帧才能"等按键，但也别永远等"；
      ④ AI 对话期间把 `isTriggered` 收到**只认玩家真实输入**，
         把第三方的"自动推进 / 播放模式"挡在外面（对话结束立刻恢复）。

  二、文本框仍然错行 —— 折行宽度不再"照公式猜"，改用**真实消息窗口**量

    原来用 `boxWidth − padding×2 − 168`，只在引擎原版下成立。
    真实游戏里有插件会改正文起点（`newLineX`）、行高、立绘旁白框宽度 ——
    一旦实际起点不是 168，折出来的行就与窗口对不上：行尾被裁（字跑到框外）
    或者右侧空出一大块（看着"对不齐"）。
    现在只要场景里真有消息窗，就用它的 `contentsWidth()` 与 `newLineX()` 实时算，
    两边取更保守的那个；量不到（无头测试）才退回公式。
    这是"换一款游戏就可能对不上"的**通用**修法，不是给《Mira》打补丁。

  三、人设没同步到角色面板 —— 面板那一行**只读原作身份，不看人设卡**

    「AI 角色」菜单（当前地图的角色面板）原来显示的是 `n.role`（**原作身份**，如"学生"）
    与 `displayName()`（顺序是 actors_ai → npc.name → role → eventName）。
    而人设生成器**只写 `n.persona`、不覆盖 role** ——
    于是写完人设面板上毫无变化：名字没变、身份还是"学生"、也没有任何"已写过"的痕迹。
    （资料馆「角色」栏读的是人脸卡，所以那边一直正常 —— 两边口径不一致。）

    修法：菜单改为**以人设卡为准** ——
      · 名字取卡里的名字、身份取卡里的 `identity`；
      · 行里给有卡的人画一个 `✎` 标记，一眼就能确认"已经写进去了"；
      · 本图一个可扮演角色都没有时（《呆呆》很常见），把**其它地图上已写人设的角色**
        附在下面（最多 12 个 + 计数 + "还有 N 个"），并按**写入时间倒序** ——
        玩家问"我刚写好的去哪儿了"，最后写的排最前。
      · 工坊跑完顺手清掉资料馆详情页的缓存，保证"写完立刻能看到"。

  四、新增守门员 **_probe_sync.js（37 项，四台全绿）**：
    ① 翻页 16 例（中间屏 / 最后一屏都保留 pause · 不 terminate · 兜底自己数 ·
       兜底到点自己推进 · 玩家按键立刻清计时 · isTriggered 闸门 · 对话结束恢复）；
    ② 折行宽度 7 例（有真实窗口按它算 · 窗口变窄跟着变 · 量不到退回公式）；
    ③ 人设同步 11 例（名字 / 身份 / hasCard / 字数 / ✎ 标记 / 空图附列，

 v2.10.2：互动文本的「对不齐 / 闪太快」+ 人设生成从 85 次请求降到 23 次
------------------------------------------------------------------

  玩家原话：「互动时文本显示有问题：mira里互动文字对不齐，出现空格、错行；
             还有些游戏会文本显示极快，人没看清楚文本框就没了；
             再查查呆呆角色卡怎么生成那么慢」

  一、「对不齐 / 空格 / 错行」—— 真因是**控制字符没洗干净**，不是折行算错

    三个字符各有各的破坏力，都是"从 Windows 文本里粘台词"留下的：
      · `\r`（CRLF 的第二半）—— 引擎把它当普通字**画**（画出来是空的），
        但 `textWidth("\r")` 会**返回一个宽度**（实测 14px）⇒ 折行时照样占位，
        于是行尾凭空多出空白、下一行起点看着就错位；选项窗的 maxChoiceWidth 也算它。
      · `\t`（制表位）—— 同样"画不出来但占宽度"，且宽度与排版无关 ⇒ 更歪。
      · `\f` —— **最狠的一个**：引擎认得它 = 「新的一页」，会触发
        `processNewPage → startPause` ⇒ 我们的钩子以为"这一条说完了" ⇒
        `terminateMessage()` ⇒ **从这儿往后所有页连同选项一起消失**。
    修法：新增文本清洗口，挂在两个必经点上 ——
      ① 折行函数开头（一切上屏文本的必经之路；调用点多到没法逐个清）；
      ② 世界书**入库时**（地名 / 身份 / 原作台词 / 菜单名各有各的注入点，堵源头）。
    裸 `\r` 是**删掉**而不是换成 `\n`（它本来就是"同一行的重复换行符"，换行会凭空多一行）。
    刻意不碰 `\n`（分段是正当用法），也不碰中文标点与引号。

  二、「文本显示极快，人没看清楚就没了」—— **最后一屏拿到的是 0 帧停留**

    两条路不对称：中间屏排满了走 `processNewLine → startPause()`，那时记号还在，
    于是拿到一整段阅读停顿；**最后一屏**画完走 `onEndOfText() → startPause()`，
    记号早就没了 ⇒ 直接 terminate。碰巧是「先走了 / 没反应了」这类**后面没有选项窗**
    的收尾，就等于"字一画完就消失"。
    修法：最后一屏也停下 —— 把终止改成**延迟执行**，由每帧检查：
      停顿走完就收尾 · 玩家按确定键可立刻跳过 · 对话被中断也照样收尾。
      用每帧检查而不是 setTimeout —— 游戏暂停 / 切场景时必须跟着停。
    默认值 `pageWaitFrames` 60 → **120**（≈2 秒）。
    ★ 已装机器上写着历史默认值（20 / 60）的会自动迁到 120；
      玩家自己调过的值一律不碰（那是一次一个值的历史默认值，不是"一整块旧配置"）。

  三、呆呆角色卡生成慢 —— 分组按**地图**，切块按组内人数，两边一撞就爆炸

    量出来的账：呆呆 447 个成员摊在 **131 张地图**上，其中 **75 组只有 1 个人**；
    而切块是 `ceil(人数 / 每组上限)` ⇒ "不足一组"的那些各自独占一次请求：
      首轮 **162 次**请求；重要角色档（134 人 / 84 张图）要 **85 次**；
    每次请求的固定开销约 5.2KB 提示词（世界观 2.7KB + 范例 1.8KB + 规则 0.7KB），
    却只为 1 个人写卡 —— 串行跑完就是几十分钟。
    修法两条：
      ① **按容量跨地图打包**：攒够上限才切一块，不再"一组一块"。
         重要角色 85 → **23** 次（-73%）、全部角色 162 → **75** 次（-54%）。
      ② **并发**（默认 2，可在 persona_prompt.json 里调到 1~6）：
         每块失败照样自动缩批补跑，只是"何时开始下一块"改成"有槽位就开"。
    合并会丢"他在哪儿"吗？不会 —— 成员卡里本来就该有地点，
    现在**只在块内地点不一致时**给「原作定位」补一句「（所在：…）」，
    且**不动提示词模板**（装在机器上的那份可能被改过，不能强推新版）。
    不传该参数时（单人生成 / 老调用点）输出与以前**逐字节相同** —— 有探针钉住。

  四、顺带修掉一个**无头台的保真缺口**（它差点让上面第二条"验不出来"）

    测试台原来 `Ainpc.config = 读(config.json)` —— **整体替换**；
    而磁盘上的 config.json 是安装器生成的（94 键），插件 DEFAULTS 有 **161** 项 ⇒
    测试台里那 67 个"没写进 config.json 的默认值"全是 undefined。
    插件每处读取都有兜底值，所以跑起来看不出问题 ——
    但**只要有人在默认值上调参，测试台就永远验不到**。
    现在改成与真实游戏同口径：DEFAULTS 打底 → config.json 只覆盖它有的键。
    ★ 这是「默认值三方漂移」的第三种形态：**读取侧的漂移**。

  五、新增守门员 **_probe_text.js（44 项，三台全绿）**，专盯这三类：
    · 控制字符 15 例（含"不许把 \n / 中文标点弄坏"的反向断言）+ 世界书零残留；
    · 翻页停顿 10 例（停顿没走完不许动 / 走完才收尾 / 按确定可跳过 /
      中断也收尾 / 不许用 setTimeout）+ 默认值与自愈规则；
    · 批量打包 10 例（两档请求数必须显著下降 / 可退回旧行为 / 并发上限 /
      **不合并时输出与旧版逐字节相同**）。

  六、本版**没有新增任何配置项**，不用改 config.json；
     老存档 / 老世界书 / 老 config.json 全部兼容。工具链（tools/）一个字没改。

 v2.9.17：多语言游戏的正文全是占位符 —— 现在会自动还原成真台词、真名字
------------------------------------------------------------------

  起因：Steam 又下载了三款，其中《Knights of Messiah IF》装完一切"正常"，
  但打开 AI 扮演菜单，角色名是这样的：
      ${text.message101000}   ${text.message101005}   ${text.message101076}
  台词更夸张 —— 一场 74 句的戏，句句都是 ${text.message000745} 这种。

  ① 这是怎么回事
    那款游戏用了一个多语言插件（ODW_MultiLanguageSystem），把**所有正文**都换成了
    `${code}` 占位符，真值放在游戏目录的：
        languages/<语言>/main.json      ← 平铺键，形如 "text.message101000": "アリシア"
    游戏里由那个插件在**绘制文字时**替换，所以玩家看到的是一切正常的 ——
    只有我们这种直接读 data/*.json 的工具会原样拿到占位符：
      · 人名变成 ${text.message101000}，直接摆进菜单；
      · 整份语料是 512 种 ${text.xxx}，AI 拿它写世界观和人设 = 纯编。

  ② 做法：还原，规则与游戏内那个插件**逐字同口径**
    · 占位符正则照抄它源码里的 /\$\{([\w|\.]+)\}/gm；
    · 自动找语言表（languages / lang / i18n …），按游戏的 System.locale 选语言，
      找不到对应语言就取键最多的那张；命令行还能用 --lang=<文件夹名> 指定；
    · **未命中的 code 不瞎猜**：原样保留，然后从名字/正文里剔除（它会变成垃圾话）；
    · 扫描器（世界书）与语料抽取器都接了同一条还原链。
    实测：世界书里 512 个占位符，**512/512 全部还原成功** ——
    角色名从 `${text.message101045}` 变成「アリシア」「セリス」「リッツ」「マヤ」，
    台词也从占位符变回完整的日文对白（45 条角色名、41 行人物档案全部重算）。

  ③ ★ 没有多语言的游戏：一个字节都不会变（这是硬红线）
    11 款已装游戏（伊莉莎 / Mira / 4 台自建测试机 / 水族馆 / 呆呆 / Routine Soul /
    Euplectella / Level C-1366）用新旧扫描器**逐款对拍**：
        worldbook.json 差异 0 行 · actors_ai.json 差异 0 行 · 丢 0 条 · 改名 0 条。
    找不到语言表时整条链是空转 —— 连新增的记账字段都不写，产物逐字节不变。

  ④ 边界：两款又是别的引擎
    同批下载里《2b》是 VX Ace（Game.rvproj2 + RGSS300.dll），
    《终末序曲》是 XP、《The Shell of Permafrost》是 VX Ace —— 均为 RGSS（Ruby）引擎，
    与 MV/MZ 的 JS 插件体系没有交集，安装器会明确说明并拒绝（退出码 2）。

  ⑤ 一个不太起眼但会咬人的问题：语言表找错了游戏
    扁平布局下「游戏根目录」其实可能是 Steam 的 steamapps/common/ —— 那里躺着
    **别的游戏**的 languages/。不加护栏就会把邻居的语言表拿来套（串味且完全静默）。
    现在只有「父目录本身就是个游戏根」（有 index.html / package.json / Game.exe）
    才允许往上找；另外 NW.js 每个游戏都自带的 locales/（放 .pak 的那种）也不算语言表。

 v2.9.16：日文事件标签不再当人名；新增「通用启发式」（换语言也不必再补词表）；安装器认引擎
------------------------------------------------------------------

  ① 日文事件名被当成人名（v2.9.15 只覆盖了中文那一半）
    在 Steam 新下载的 MZ 游戏《水族馆不会跳舞(簡)》上实测：中文发行、事件名却是日文，
    303 条 npc 条目里有 62 条的名字直接就是事件标签，会原样摆进 AI 扮演菜单：
      回想 / 診察室 / カフェ / 2号車 / 地下 / 包帯１ / 水族館6　巨大水槽 /

    做法：

      · 加「机器前缀」剥离：`EV020:トト` → `トト`、`21:クラゲ調査` → `クラゲ`；
      · 加「动作后缀」剥离：`レトロに会う` → `レトロ`、`キティ話す` → `キティ`；
      · 加「尾部个体编号」剥离：`ピラニア3` → `ピラニア`、`レトロ２` → `レトロ`。
    实测 62 → 18 条，剩下 18 条全是真名（トト / 露露 / 克莉丝 / 蕾忒罗 / カワウソ …）。

  ② ★ 更重要的是加了一层「通用启发式」——**不再依赖词表**
    词表永远追不上全世界的游戏：上上版补英文、上一版补中文、这一版补日文，
    下一款换个语言又要再来一遍。而中日文的人名有一些**结构性**的共同点，与词表无关：
      · 不会含空白（`水族館6　巨大水槽` 是地点）；
      · 不会含标点 / 省略号（`从上面的某种东西让人恶寒啊...` 是句子）；
      · 不会长过 10 个字；
      · 不会以助词（が / を / は / の / に / で …）或状态词（いる / ある / たく …）收尾；
      · 片假名 + 方位（`ヤドカリ下`）是站位标注，不是名字。
    这些判据一个词表都不用，于是**换任何语言的 MV/MZ 都成立**。
    真名一个都没误伤，连常见日本姓（田中 / 山下 / 川上）都特意放行。

  ③ 安装器现在认识「别的 RPG Maker 引擎」
    同一批下载里还有两款老引擎：《The Shell of Permafrost》是 VX Ace（Game.rgss3a）、
    《终末序曲》是 XP（Game.rgssad）—— 它们用 RGSS（Ruby），插件体系与 MV/MZ 完全不同，
    本插件不可能通用。以前安装器只会说「找不到 data/System.json，确认一下游戏根目录」，
    玩家会以为是自己路径填错、反复试。现在直接点明：
      ✘ 这是 RPG Maker VX Ace 工程，本插件只支持 MV / MZ。
    并解释为什么（RGSS 是 Ruby 引擎）。MV/MZ 之外的引擎一律**明确拒绝**，不装。

 v2.9.12：自由输入不再必崩 —— 「打字」这条路能走了
------------------------------------------------------------------
  症状（玩家原话）：「自由对话，输入会报错」。
    实际是**一按「保存」就崩**，弹出一个引擎报错帧：
      TypeError: Cannot read property 'indexOf' of undefined
    不是「某句话认不出来」，而是这条功能 100% 不可用。

  根因：判断「玩家这句话是不是在讲价 / 要买 / 要偷」的函数里写了
      re.flags.indexOf('g') ———— 而 `RegExp.prototype.flags` 是 **ES2015**
      才有的访问器（Chrome 49+）。这部游戏是 **Chromium 41**，那里 `re.flags`
      是 `undefined`，接着 `.indexOf` 当场抛错。
      伊莉莎是 Chromium 65，所以只有 Mira 上会崩。
    改成手动拼修饰符，等价且老引擎安全（`/gi` 与 `/ig` 完全等价，顺序无语义）。

  ★ 这个 bug 为什么躲过了当时 30 个全绿的测试（值得记一笔）：
    ① 自由输入这条路**一个测试都没有** —— 已补 `_probe_intent.js`（22 项）；
    ② 测试台跑在 Node 22 上，`RegExp.prototype.flags` 在那儿是存在的；
    ③ 连「把 flags 删掉再冒烟」也测不出来 —— 插件跑在隔离上下文里，
       而**正则字面量用的是那个上下文自己的内建原型**（永远有 flags）。
    ⇒ 这类「新引擎有、老引擎没有」的访问器，**只能靠静态名单拦**。
      已把 `RegExp.prototype.flags` 加进 `audit_mira.js` 的禁用名单，
      并实测：拿它去测未修的旧包会**指着 L7275 报错**，测本版全绿。

  同一版顺带调了一个显示参数：**一屏放不下时的自动翻页，每页停留 20 帧 → 60 帧**
    （60 帧 ≈ 1 秒）。原来那句注释写的是「一小段阅读停顿」，可 20 帧只有 0.33 秒，
    一行 35 个字根本读不完 —— 长台词会一屏一闪而过。
    这个键叫 `pageWaitFrames`，想更快/更慢就在 `ai_npc/config.json` 里改它
    （0 = 立刻翻，不等待），现在也写进了 `config.template.json` 供参照。

  地图上摆着的椅子、火焰、伤害数字、敌人素材图，也会被当成 NPC 收进人设名单 ——
  给一把椅子写一份人设，纯粹是白花额度。

  以前是靠一份**写死的名单**（mom_object01 / MVenemies_02 / Damage1 / Nature …）。
  那两个 `mom_object` 是从具体作品里抄来的，换一部游戏一条都不会命中。

  现在改成**两层模式判据**，任何 RPG Maker 作品都成立：

    · 引擎自带素材名 —— Damage1~3（伤害数字）、Nature（自然景物）、Vehicle（载具）、
      Shadow（影子）、Transparent（透明占位）。引擎随包分发，哪个游戏都叫这个名。
    · 语义关键词 —— object / furniture / decor（摆件）、effect / particle（特效）、
      enemies / battler（战斗素材表）、float（漂浮物）、vehicle / marker。

  判据一定有覆盖不到的素材名，所以留了两个口子（不用改代码）：

    node tools/build_persona_input.js --www="…" --nonHuman=椅子,桌子    ← 判据漏了，补上
    node tools/build_persona_input.js --www="…" --keepSprite=Slime     ← 判据误杀，放行

  每次打包都会把「剔掉的立绘名 × 次数 —— 命中了哪条规则」列出来，一眼看得出有没有误杀。
  漏掉的后果也很轻：它们会落进「纯路人」档，默认的「生成重要角色人设」根本不会写它们。

  实测：伊莉莎仍剔 10 条（与旧写死名单**逐条相同**），Mira 零命中 ——
  两部游戏的人设线索包**逐字段零差异**（148/44/33 与 110/55/15 全不变）。


------------------------------------------------------------------
 v2.9.7：读懂「这是哪儿」—— 地点解析通用化
------------------------------------------------------------------
  换一部游戏，AI 常常不知道自己在哪。根因是地图名的命名有好几派，
  而解析器**只认一派**。

    · 路径派  MAP010/area01_hel_town_in_church_1F_01   → 赫尔镇 · 教堂
    · 编号派  004：校門 / 029：夢の世界               → 以前整片解析不出

  路径派能翻译，编号派就抓瞎 —— 于是模型收到的「你现在所在」是一串
  带编号的原始地名，甚至干脆是内部文件名。

  这一版三派都认：

    路径派   areaNN_鎮_设施            →「赫尔镇 · 教堂」
    编号派   NNN：地名                 →「アウイル › 学校 › 校门」
    通用派   Game / dungeon / town     →「主线剧情演出场景」等引擎惯用图名

  编号派是这次的重点。这类地图名往往带 parentId 层级（`004：校門` 的父是
  `002：学校`，再上是 `001：アウイル`），而**整条链一直存在世界书的 mapPaths
  里、从来没被用过**。现在把它拼出来 —— 「アウイル › 学校 › 校门」比光秃秃
  一个「校门」给模型的语境强得多。

  顺带修好了两处一直存在的小毛病（旧的内联解析器）：
    · `_in` 误命中 `_INN`：给「赫尔镇 · 教堂」硬加了一个「室内」；
    · 切片时把首段的前导下划线吃掉，`dungeon_map01` 认不出「地牢」。
  伊莉莎这类游戏的地名会因此变得更干净、更完整。

  解析不出来时**优雅降级**：退回原名（而不是乱猜）；若原名是内部路径
  （对模型是纯噪音），才退到「商店 / 教堂」这种粗粒度场合词。

  日文地名做了小范围中文化（学校 / 教室 / 屋敷→宅邸 / 地下水道 …），
  但**专有名词一律保留原文**（アウイル、ロシェ 这些人名地名硬翻反而会翻错，
  模型看原文照样懂）。

  如果你是 Mira 这类游戏：升级完请重跑一次「一键准备」，地名线索就会更新。

 v2.9.6：一键只写「重要角色」—— 人设生成从「全量」变成两档可选
------------------------------------------------------------------
  有人问：全写一遍太贵了 —— 能不能只写重要的，但「全写」也要留着？可以了。

  菜单「AI 角色」里现在并排两条入口，人数直接写在后面：

      ✦ 生成重要角色人设（省额度 · 推荐）   （33 人）
      ✦ 生成全部角色人设（深度扮演）        （148 人）

  点进去之前就知道这一趟要跑多少次调用，不用跑完才发现烧掉一堆额度。
  两条路都在，选哪条由你决定。

  「重要」怎么判 —— 不写死任何作品名，只用「任何 RPG 都成立」的结构特征：

      core   主角团，或台词 ≥ 30 句          → 戏份重的人话一定多
      major  台词 ≥ 5 句，或有明确职业身份    → 商人这类 0 台词也少不了他
      minor  有台词，或原作写了说话人变量     → 原作里他真的会开口
      extra  纯路人（没台词、没身份、没变量）

  默认「重要」= core + major。实测：

      Mira  148 人 → 只写 33 人（省 78%）
      伊莉莎 110 人 → 只写 15 人（省 86%）

  **没写到的路人不会被冷落**：插件本来就按原作台词演，跳过他们只是「没有独立
  性格」，不会变成哑巴，游戏行为一点不变。

  想改「什么算重要」：编辑 ai_npc/persona_prompt.json 里的 importance 段 ——
      "tiers": ["core", "major"]     →  只想要主角就填 ["core"]
      "majorLines": 5                →  调低到 2 会多写一批配角
  这是配置不是代码，换一部戏份分布不同的游戏也不用改插件。

 v2.9.5：认准「谁是谁」—— 角色身份识别重写
------------------------------------------------------------------
  上一版把 121 个路人从「商人」里摘出来之后，有玩家立刻发现另一个极端：
  **一个商人都没有了**。这版挖到了底。

  根因（Mira 这类游戏）：它不用「事件指令」写 NPC，而用一个插件把身份写在
  **注释**里，运行时再把事件本体的指令整体替换成一个调度器公共事件
  （◆MobBranch）。于是：

    · 事件本体里既没有台词、也没有商店 —— 只看本体的扫描器**什么也认不出**；
    · 身份只存在于注释（+type7 / +actor17）与调度器的分支条件
      `if (变量10「◆mobBranch」 == 7 / 8 / 33)` 里，其中只有 7、8、33 通商店。

  这一版把两处都解析出来，判定从「猜」变成「按分支归属」：

    · **真商人认出来了**：Mira 的 4 个梦境商人（夢の世界：+type7 卖草药素材、
      +type8 卖杂货）现在被正确标成「素材商人」，并记下在售商品。
    · **路人不再是「居民」一锅粥**：立绘名 + 地图名一起用 —— Mira 原来 151 个
      「居民」变成 100 学生 / 7 魔女 / 3 魔物 / 1 宅邸的人。
    · **认不出的仍保守记「可交易」**，不动任何运行时能力（买 / 讲价 / 偷照旧可用）。

  顺带修好了人设生成的最后一段路：以前的「原作定位」字段算了却**从没渲染进
  提示词**，等于白算。现在它（连同商人的在售商品）会真真切切喂给模型 ——
  没有台词、没有名字的商人，全靠这一行来定他是谁。

  这一版对**伊莉莎**是零差异：它的世界书 455 条逐字段比对完全一致
  （伊莉莎没有这套注释标记，新判定一条都不会触发）。

  包里有对比工具：tools/cmp_worldbook.js 可逐字段比对任意两份 worldbook.json。


------------------------------------------------------------------
 v2.9.4：人设生成不再「老是解析失败」+ 商人标签不再满天飞
------------------------------------------------------------------
  两件被反复抱怨的事，根因都不在模型。这一版把它们一起修了：

  · 「生成角色设定时老是 JSON 解析失败」—— 三重叠加，逐个拆掉：

    ① 超时过短（主因）。config 里的 30 秒是给**聊天**定的，可生成一组
       人设要吐 5~8 张长卡，实测 8 人一组要 44~54 秒。时间一到我们就把
       电话挂了，模型其实正在好好写。→ 人设单独走一条宽超时（默认 180 秒），
       写在 persona_prompt.json 的 batch.callTimeoutMs 里，可自行改。

    ② 思考抢占了输出的额度。思考型模型（deepseek-flash / R1 那一系）的
       max_tokens 是「**思考 + 正文**」共用的。实测出现过「思考 7944、
       正文只剩 56 token」的情形 —— 正文被截在字符串中间，一张完整卡都
       救不回来。→ 输出上限提到 16000，并把每组人数从 8 收到 6，给思考
       留出余量。

    ③ key 对不上就整批丢弃。以前是严格相等匹配，模型把 key 抄成全角冒号、
       或大小写不一致，整批全废，还只报一句「解析不出 JSON」。→ 现在三档
       兜底：原样 → 自动归一（全角冒号/空格/大小写）→ 万不得已按顺序回填；
       并且把失败原因分开说清楚（正文为空 / 被长度截断 / 真解析不出），
       原始回复落盘 ai_npc/persona_last_fail.json，方便自己排查。

  · 「世界书里一大堆人标签是商人」—— 世界书扫描器的误判：
    有些游戏用一个公共事件当「通用路人调度器」，里面在某条选项分支下
    顺手埋了几条商店指令。旧扫描器「见到商店指令就算商店」，于是整条
    调度器被当成商店，**上百个路人一起变成商人**。→ 改成按「商店纯度」
    判断（商店指令占实质内容过半才算本质是商店），并给解释器加了分层守卫。
    结果：误判归零，身份回落「居民」，但货架信息照旧保留（买 / 讲价 / 偷
    一样能用），另给一个「可交易」标签做提示。

  ★ 插件本体与 www/ai_npc/tools/ 是两个独立目录，**必须同版本号一起换**。

 v2.9.3：老引擎兼容（Mira 这类 NW.js 0.12 / Chromium 41 的游戏）
------------------------------------------------------------------
  同一份插件以前放进这类老引擎游戏，菜单里**根本没有「AI 角色」**——
  不是菜单没挂上，是整份脚本在编译阶段就失败了。现在三处一起修好：

  · 插件本体：删掉两处「对象字面量的重复属性名」。ES5 严格模式下这是
    SyntaxError（Chromium 41 直接拒绝整份文件），而 ES2015 起放宽为
    「后者胜」，所以新引擎上一直没人发现。另外 Array#find 是 ES6，
    也换成了 ES5 写法。

  · 游戏内工具：www/ai_npc/tools/ 下那 10 个脚本整体降到 ES5。它们不是
    普通命令行脚本 —— 插件是用 new Function 把它们塞进**游戏自己的 Node**
    里执行的，老引擎只认 ES5，一行 ES6 语法就会让「一键生成」点了没反应。
    老引擎缺的 Object.assign / Object.entries / Object.values、
    Array#find / Array#includes、String#padStart / padEnd 已就地补齐
    （新引擎原样跳过，一行都不生效）。

  · 配置面板：面板 CSS 用了 CSS 变量（Chrome 49+），老引擎会把整条声明
    丢掉、掉成白底黑字。现在每条 var() 前面都补了一份字面值兜底，
    新引擎行为一字不变。

  ★ 插件本体与 www/ai_npc/tools/ 是两个独立目录，**必须同版本号一起换**：
    只换插件不换 tools/，老引擎上的「一键准备」照样跑不起来。
